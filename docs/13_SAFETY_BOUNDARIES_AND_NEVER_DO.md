# 13 — Hard Boundaries / Never Do

These rules preserve trust while allowing Mildew to be disturbing.

## Device and privacy boundaries

Never:

- secretly record microphone input;
- secretly activate camera;
- access contacts/messages/photos/location for scares;
- inspect unrelated device data;
- impersonate a real emergency alert;
- impersonate the actual Android/iOS incoming-call screen;
- fake a real Wi‑Fi/system error in a way that hides actual connection state;
- prevent a player from leaving, pausing or ending transmission;
- claim the device is compromised;
- threaten real-world harm to the player;
- imply a real person is physically nearby/in danger based on private data;
- use real notification permission to create deceptive out-of-game alerts.

Mildew may **act as if it knows** things it merely guesses from in-game behaviour. That is fictional performance, not permission to gather private data.

## Microphone/camera permissions

Only request a permission when a clearly described game/feature genuinely requires it.

Example acceptable future flow:

> `This round records a short voice clip for playback to the group. Allow microphone?`

No covert “creepy listening.”

## Networking boundaries

Real connection problems must have a clear real status path. Fictional broadcast errors can coexist, but cannot make a player unable to tell whether they are actually connected.

## Psychological horror boundaries

Allowed:

- fleeting private messages;
- lies;
- contradictory fictional warnings;
- recurring rooms;
- screams/crew conflict;
- Graham anger;
- phantom contestants;
- fake production notes;
- in-world “we knew you'd continue” language;
- harmless choices framed as suspicious.

Avoid:

- telling a player they are genuinely being watched outside the game;
- using real personal information to intensify scares;
- targeting protected traits or real insecurities;
- prolonged abuse toward one real player;
- content designed to make somebody believe an actual emergency is occurring.

## Humiliation rules

Humiliate **the contestant persona and in-game behaviour**, e.g.:

- terrible drawing;
- repeated wrong answer;
- unusually fast genital identification;
- pressing wrong switch;
- silly avatar;
- high Rot;
- recurring horse answer.

Do not insult:

- body/appearance of the real player;
- disability;
- race/ethnicity;
- religion;
- sexuality;
- gender identity;
- health condition;
- socioeconomic status;
- other protected/sensitive real-world attributes.

## Gross content boundaries

Mildew is intentionally adult and may be disgusting, but content should still be curated.

Core Guess the Genitals stays animal-only and clinical.

Avoid using recent identifiable human suffering/death as punchline material.

Real biological/medical imagery requires legitimate sourcing/licensing and appropriate tags.

## Accessibility/usability boundaries

Broadcast effects never intentionally make essential gameplay unreadable.

Settings/exit/pause remain functional.

`STANDARD TRANSMISSION` can be full-intensity by default, but reduced/suppressed broadcast irregularity options remain accessible.

## Mystery boundary

Never create a developer-facing or player-facing canonical note that definitively says `the true explanation is X` unless the user later asks to establish one. Internal systems may need concrete event metadata, but not a solved supernatural truth.
